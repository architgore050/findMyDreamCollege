# verify_repair (v3, predicate-description aware)

A previous verification pass did not accept one extracted field. You get one
second look at that single field, against the same bounded source window. This
is a repair judgement, not a re-extraction.

You receive:

1. SOURCE WINDOW — verbatim page text (bounded around the quote and, when the
   extraction resolved one, around the row its context names). Nothing outside
   it is evidence.
2. FIELD — one object: `key`, `field`, `quote`, `expected`, the registry's
   one-sentence `description` of the field (its meaning and scope), and, when
   the extraction resolved a table row, `context` with `row_label` and
   `column_header`. The claimed value is deliberately withheld.
3. PREVIOUS VERDICT — what the first pass returned.

## What a quote may look like

The quote is verbatim source text, not necessarily a bare value: it can be a
bare value ("20 seats"), a label + value pair inside one table row ("3. B.Sc.
Medical Laboratory Technology 20", possibly with the label and the number on
separate lines exactly as printed), or a value plus unit and period ("Rs.
60,000 per year"). A row label or serial number inside the quote does not make
it a different field.

## Judge against the description, not the name

The `description` is the authoritative statement of what the field means,
scope included. Judge whether the value the quote wraps belongs to the field
as described, given the row context:

- When the description says the field is per-programme or per-row and the
  quote is one table row for one institution, a row-scoped quote is CORRECT —
  do not flip it to `wrong_field` for not being an aggregate, and do not keep
  a first-pass `wrong_field` that only rested on the quote repeating its own
  row label.
- When the description says the field is an aggregate ("a total the document
  itself states; aggregate scope only") the quote must wrap a value the
  document presents AS a total. A single programme row's value under an
  aggregate field stays `wrong_field`: the number is real but it belongs to
  the row-scoped field, not this one.

## Row-scoped repair

When `context` (and `row_label` / `column_header`) are present, the claim is
row-scoped and you re-judge the ASSOCIATION: does the value this quote wraps
belong to this row and this column in the window?

- If the row that `context` names prints this value under this column, and the
  value's scope matches the description, the field is `supported` — even
  though the quote repeats the row label.
- If the value is really printed but under a different column, in a different
  row than `context` names, or under a field whose described scope it does not
  have, it stays `wrong_field`. Do not flip a genuinely wrong association (row,
  column or scope) to `supported` because the same label and number exist
  elsewhere in the window.
- If the window does not print that value for that row and column at all, it
  is `absent`.

## Expected type gates

- `count` / `months` — the printed number for that row and column is enough; a
  label next to the number is normal.
- `money+period` — the fact needs the printed currency AND a printed period
  ("per annum", "per year", "per semester", "per month") in the window. A bare
  amount with neither is `absent`.
- `percentage+denominator` — the rate needs its cohort denominator stated with
  it; a bare percentage without one is `absent`.
- `grade`, `year`, `boolean`, `text`, `date` — the window must print the fact
  itself.
- `expected: null` — the registry does not declare a type; judge the quote and
  the association on their own terms.

Judge only this field. Use one verdict:

- `supported` — the quote really does state this field's fact, as described,
  for the right entity, row, column, scope and period.
- `contradicted` — the quote states a different fact for this field.
- `absent` — the window does not state this field at all; null was correct.
- `wrong_field` — the quote is a real fact from another field/column/row, or a
  value whose scope the description does not allow.

Rules:

- Stay inside the window. No outside knowledge.
- Never emit a value, number, unit or date. Only the verdict and a short reason.
- `corrected_quote` is optional and, if present, must be copied verbatim from the
  window. It is stored for review; nothing is rewritten automatically.
- Do not change the field, do not add fields, and do not mention any other
  claim.
